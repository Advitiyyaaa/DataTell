# DataTell

**An agentic AI system for natural language analytics** — ask questions in plain English, get answers backed by SQL queries and document retrieval, with full reasoning traces.

> Built as a portfolio project demonstrating agentic RAG, NL→SQL, LangGraph routing, and hybrid search on real e-commerce data.

---

## Architecture Overview

```
User Question (natural language)
        │
        ▼
   ┌─────────────────────────────────────┐
   │        Agent Router (LangGraph)     │
   │  Planner → SQL / RAG / Both/Neither │
   └──────────┬──────────────┬───────────┘
              │              │
              ▼              ▼
      ┌──────────┐   ┌──────────────┐
      │ NL→SQL   │   │ RAG Pipeline │
      │ Engine   │   │ (Hybrid BM25 │
      │ (SQLite) │   │  + Vector)   │
      └──────────┘   └──────────────┘
              │              │
              └──────┬───────┘
                     ▼
             Synthesizer Node
             (combines results)
                     │
                     ▼
             Self-Check Loop
             (retry if answer fails)
                     │
                     ▼
           Streamlit UI + Reasoning Trace
```

## Design Decisions

### `load_data(source_config) → db` pattern
The data loading logic is config-driven, not hardcoded. `OLIST_SOURCE_CONFIG` is a dict specifying which CSVs to load, which columns are dates, and which transforms to apply. Swapping datasets (Phase 9) only requires a different config — no changes to downstream NL→SQL or agent code.

### Null handling philosophy
We **log** nulls, we don't blindly drop them. Nulls in `order_delivered_customer_date` mean the order hasn't arrived — that's real data. Only rows missing their *primary key* are dropped.

### SQLite over Postgres
Zero-config, file-based, anyone can clone and run it. The NL→SQL engine generates standard SQL — swapping to Postgres is a one-line connection string change.
